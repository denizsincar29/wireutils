# wireutils — состояние

Обновлено 2026-09-24.

## Что это

Одно приложение: держит один `hosts.json` (Windows → `%APPDATA%\wireutils`,
Linux → `~/.config/wireutils`), в нём — путь к папке VPN-конфигов и список
хостов. Список превращается в один и тот же `AllowedIPs` и пишется во **все**
`.conf` этой папки («один конфиг для всех конф файлов», ответ 1 от 24.09).

## Готово (ядро, 82 теста зелёные, container-verifiable)

| Модуль | Что делает |
|---|---|
| `src/wgconf.rs` | Парсер/писатель `AllowedIPs` в `.conf`. Правит **только** эту строку, всё остальное (ключи, комментарии, порядок, `\n`/`\r\n`, отсутствие финального перевода строки) сохраняется побайтово. Понимает `AllowedIPs = a, b`, `AllowedIPs=a,b`, `allowedips=`, отступы. Не путает с `AllowedIPsList`. |
| `src/hosts.rs` | `hosts.json`: `version`, `conf_dir`, `groups`, `hosts[]` (target/groups/ips/source/error). Добавление дубля обновляет, а не плодит. Группы, переименование, флаг неразрешённых. `is_address()` принимает IP и CIDR (v4 ≤32, v6 ≤128). |
| `src/resolve.rs` | Домен → адреса через системный резолвер. Провал **сообщается** и остаётся в файле (`error`), кэш не затирается. `FakeResolver` для тестов. |
| `src/templates.rs` | Каталог шаблонов: вшит в бинарь (`data/templates.json`, 18 групп) + загрузка по HTTP/`file://`. Битый или пустой апдейт отвергается, апдейт **не может удалить** вшитые группы. Поиск по имени и ключевым словам (`instagr` → instagram). |
| `src/apply.rs` | Запись во все `.conf` папки. Не меняет файл, если значение уже такое (идемпотентно). `.conf.bak` перед первой перезаписью; чужой бэкап не трогает. Файл без `AllowedIPs` — `SKIPPED`, не выдумываем `[Peer]`. Неразрешённый хост → отказ целиком. |
| `src/import.rs` | Импорт стартового списка из базового конфига: читает `AllowedIPs` нужного `.conf`, каждая адресная запись становится хостом. Имя даёт PTR, иначе подсеть (`/24` v4, `/48` v6), в последнюю очередь — сам адрес; все пути сходятся в один `BTreeMap` по имени, поэтому дедуп происходит один раз. **Гибрид** (ответ 2 от 24.09). `0.0.0.0/0` распознаётся как full-tunnel и отвергается: у конфига, забирающего все адреса, нет списка сайтов, который можно забрать. Путь запоминается в `hosts.json` как `base_conf`. |
| `src/paths.rs` | `hosts.json` на Windows (`APPDATA`) и Linux (`XDG_CONFIG_HOME`/`~`); override через `WIREUTILS_CONFIG_DIR` (нужен тестам). |
| `src/main.rs` | CLI: `init`, `set-conf-dir`, `show`, `add -g`, `rm`, `rename`, `group add/rm/apply`, `resolve [--force]`, `apply [--dry-run]`, `templates [QUERY]`, `templates-update [URL]`. |

E2E-прогон 24.09 на трёх фейковых `.conf`: 7 доменов chatgpt + IP → resolve →
apply → все три файла получили один список, бэкапы на месте, повторный apply =
`0 written, 3 unchanged`. Провал резолва (`nope.invalid`) → exit 1, `apply`
отказывается писать, файлы не тронуты.

E2E-прогон 24.09 импорта (чистая конфиг-папка): `import base.conf` → 3 хоста
(`142.250.74.0/24`, `198.51.100.0/24`, `31.13.64.0/24`, все в группе `chatgpt`),
и у каждого в `ips` только `/32`-адреса **из файла**; `show` печатает
`142.250.74.0/24  [chatgpt]  142.250.74.14/32`. Дальше `set-conf-dir` → `apply`
→ все три `.conf` получили `AllowedIPs = 142.250.74.14/32, 198.51.100.9/32,
31.13.64.1/32, 31.13.64.2/32`, повторный `apply` — `0 written, 3 unchanged`,
`grep -l '/24' conf/*.conf` пуст.

## Инвариант: имя хоста — не маршрут

Правило, ради которого импорт и переписывался. Адрес попадает в `ips` **только**
двумя путями: через `resolve` (реальный ответ DNS) или через `add_address`
(конфиг, который его перечислил). *Имя* — CIDR вроде `31.13.64.0/24`, которым
импорт называет группу, — маршрутом не является, как бы на адрес ни походило.

Держится в трёх точках, а не на честном слове:

- `add_host` — новый хост создаётся с пустым target (`Host::new("")`), поэтому
  CIDR-сид из конструктора не срабатывает; у существующего хоста голый-адресный
  сид снимается там же.
- `add_address` — в ветке создания сид снимается; в ветке существующего хоста
  метка снимается **безусловно** (ранняя версия оставляла её, когда замены не
  приходило, — и ровно легаси-форма, где метка была единственной записью под
  своим target, проходила мимо правила).
- `apply_import` — оставляет только то, что перечислено в файле.

Магазин, записанный до появления правила, хранит метку как адрес — и открывается
именно он, поэтому исправление живёт в `add_address`, а не во время импорта. Хост
с вытесненной меткой остаётся неразрешённым, `apply` отказывается писать: честнее
отказ, чем тихий маршрут на подсеть, которую никто не выбирал.

## Не сделано

1. **GUI на wxdragon** — фича `gui`, код написан (`src/gui.rs`, окно целиком),
   собирается и запускается на Windows у Дениза (`cargo run --features gui`,
   либо `wireutils-cli gui`). В контейнере нет wx и нет дисплея, поэтому
   компиляция `--features gui` тут ни разу не проверялась — единственная
   невыверенная часть проекта. Всё обещанное на месте: табличный список
   (домен, фолбэк на IP), добавление/переименование/удаление,
   группы (создать / добавить выбранные / удалить), поиск шаблона с
   добавлением, выбор папки при первом запуске, резолв (обычный и `--force`),
   запись во все конфиги, статусная строка с результатом.
2. **`templates-update` только проверяет загрузку** — вшитый каталог в
   бинаре обновляется пересборкой; URL по умолчанию
   `https://ai.denizsincar.ru/pipelines/wireutils/templates.json` (файла там
   пока нет).
3. **GUI-проводка импорта не скомпилирована ни разу.** `--features gui` в
   контейнере не собирается вообще: `wxdragon-sys` тянет `reqwest` →
   `native-tls` → `openssl-sys`, а openssl-sys требует pkg-config и системный
   OpenSSL, которых тут нет (и `pip`/`apt` не помогут — файловая система
   read-only вне workspace). Поэтому **ни одна** правка `src/gui.rs` за всю
   историю проекта не проходила через компилятор; этот файл — единственная
   невыверенная часть. Собирать на Windows у Дениза.
4. `.conf` с нестандартной раскладкой (ключ в нижнем регистре без пробелов) —
   обрабатывается, но реальных файлов amnesiawg я не видел; нужен один
   образец, чтобы прогнать на нём.
